# Arduino Uno/Nano + W5500: «Меркурий-200» в локальной сети

Прошивка опрашивает только накопленные показания T1–T4 командой `0x27`,
проверяет ответ и отдаёт JSON через Ethernet. Это **опрос UART через физический
приёмопередатчик CAN**, а не стандартный CAN-протокол. CAN-контроллер MCP2515
для этого проекта не используется. Счётчик подключается через PCA82C250,
схема и питание подробно описаны в [общей инструкции](../docs/hardware.md).

Проект рассчитан на классические **Uno R3 / Nano ATmega328P, 5 В, 16 МГц**.
Это не прошивка для Nano ESP32, Nano 33, Uno R4 или других несовместимых плат.

## Что входит

- `MercuryLan/MercuryLan.ino` — прошивка, сетевой сервер и периодический опрос.
- `MercuryLan/config.h` — адрес счётчика, сеть, выводы и интервалы.
- `MercuryLan/mercury_codec.*` — отдельный код протокола без зависимостей Arduino.
- `platformio.ini` — сборка Uno и двух вариантов загрузчика Nano.
- `tests/test_codec.cpp` — проверка опубликованных кадров, CRC, BCD, повреждений
  и восстановления после эха/мусора.

## Подключение плат

**Все контакты ниже — сигнальные низковольтные. Выводы счётчика нельзя
соединять прямо с GPIO Arduino.** Полная разводка PCA82C250, CANH/CANL и
питания интерфейса счётчика находится в общей инструкции.

| Arduino Uno/Nano | Устройство | Сигнал |
|---|---|---|
| D8 | PCA82C250 | RXD → приём Arduino |
| D9 | PCA82C250 | TXD ← передача Arduino |
| D10 | W5500 | CS / SCS / SS |
| D11 | W5500 | MOSI |
| D12 | W5500 | MISO |
| D13 | W5500 | SCK |
| GND | Низковольтные модули | Общий сигнальный провод |
| D4 | SD-карта на Ethernet shield, если присутствует | CS; прошивка удерживает HIGH |

Для Ethernet используйте **готовый 5-В совместимый W5500 shield для Uno** либо
модуль с документированной совместимостью питания и уровней SPI. Сам кристалл
W5500 питается от 3,3 В; голый модуль не следует подключать наугад к 5 В.
Линии D0/D1 остаются свободны для USB-загрузки и Serial Monitor.

## Настроить перед прошивкой

Откройте `MercuryLan/config.h`:

```cpp
#define METER_ADDRESS 651401UL
#define METER_BAUD 9600UL
#define METER_POLL_MS 30000UL
#define USE_DHCP 0
#define STATIC_IP {192, 168, 1, 50}
#define STATIC_GATEWAY {192, 168, 1, 1}
#define STATIC_SUBNET {255, 255, 255, 0}
```

`651401` — предполагаемый заводской адрес по номеру `00651401` на фотографии.
Адрес мог быть изменён при настройке прибора. Уточните его, если ответа нет.
Скорость 9600 — настройка проекта; реальный прибор 2006 года также мог быть
перенастроен. В этой версии скорость намеренно ограничена 9600, чтобы параметры
прошивки и аппаратной схемы оставались согласованными.

Выберите свободный статический IP в своей подсети и исключите его из пула
DHCP либо создайте резервирование на роутере. Для каждой платы задайте
уникальный MAC. Значение по умолчанию `02:4D:45:52:00:01` — локально назначенный
MAC, а не заводской адрес производителя.

При `USE_DHCP=1` прошивка ждёт DHCP примерно до 5 секунд, затем использует
статические настройки. Продление аренды выполняется библиотекой Ethernet.
Для постоянно работающей установки статический адрес проще и не зависит
от времени ответа DHCP-сервера.

## Сборка в Arduino IDE

1. Установите пакет плат **Arduino AVR Boards 1.8.6**.
2. В Library Manager установите **Ethernet by Various, версия 2.0.2**.
   Библиотека `SoftwareSerial` входит в AVR core.
3. Откройте **`MercuryLan/MercuryLan.ino`**. Файлы `.h` и `.cpp` должны оставаться
   в той же папке.
4. Выберите Arduino Uno или Arduino Nano ATmega328P. Для старых Nano может
   требоваться пункт **ATmega328P (Old Bootloader)**.
5. Соберите, загрузите и откройте Serial Monitor на **115200 бод**.
   Прошивка напечатает `Mercury LAN IP: ...`.

Вариант командной строки с установленным Arduino CLI:

```bash
arduino-cli core install arduino:avr@1.8.6
arduino-cli lib install Ethernet@2.0.2
arduino-cli compile --fqbn arduino:avr:uno MercuryLan
arduino-cli upload --fqbn arduino:avr:uno --port /dev/ttyACM0 MercuryLan
```

На Windows вместо `/dev/ttyACM0` укажите свой `COM`-порт, например `COM5`.

## Сборка PlatformIO

Из этой папки:

```bash
pio run -e uno
pio run -e uno --target upload
pio device monitor
```

Для Nano используйте `-e nano` (старый загрузчик) или
`-e nano_new_bootloader` (новый). Зависимости закреплены:
`atmelavr@5.1.0`, `arduino-libraries/Ethernet@2.0.2`.

## Чтение из сети

```bash
curl -i http://192.168.1.50/api/v1/readings
curl -i http://192.168.1.50/health
```

Оба URL отвечают одним форматом кэша. `GET /health` возвращает HTTP 200, только
если последняя попытка опроса успешна, иначе 503. Для `/api/v1/readings` действует
тот же статус. HTTP-запрос **не запускает опрос счётчика**: очередной опрос
происходит по таймеру каждые 30 секунд.

Пример успешного ответа ниже — **иллюстрация формата, не показания вашего
счётчика**:

```json
{
  "schema_version": 1,
  "device": "mercury-200",
  "transport": "arduino-uart-can",
  "demo": false,
  "meter_address": 651401,
  "ok": true,
  "error": null,
  "has_reading": true,
  "age_seconds": 3,
  "tariffs_kwh": [621.42, 208.34, 111.11, 222.22],
  "total_kwh": 1163.09
}
```

Если ответ ещё ни разу не получен, `has_reading=false`, `age_seconds=null`,
`tariffs_kwh=null`, `total_kwh=null`. Программа не подставляет выдуманные нули.
После сбоя сохраняется последняя удачная выборка, но `ok=false`, HTTP 503,
а `age_seconds` продолжает расти. Эти данные нельзя принимать за свежие.

У Arduino нет часов реального времени: абсолютную дату получения сохраняет
ваш клиент. `age_seconds` — возраст последней удачной выборки по `millis()`.
После непрерывного отказа дольше примерно 49 суток этот счётчик возраста
переполнится; `ok` останется `false`. Перезапуск платы очищает кэш.

Тарифы передаются **числами в кВт·ч с двумя знаками**. Внутри они хранятся как
целое число сотых кВт·ч, без ошибок округления float. Общая энергия вычисляется
как сумма T1–T4; это не отдельная команда чтения общего регистра.

## Ошибки и диагностика

| `error` | Что проверить |
|---|---|
| `timeout` | Питание интерфейса 5 В, CANH/CANL, GND, адрес, 9600 бод, питание самого счётчика |
| `invalid_frame` | Ответ неполный, чужой адрес/команда, неверная скорость, перепутанные линии |
| `crc_error` | Помехи, земля, согласование линии, неправильный физический интерфейс |
| `invalid_bcd` | Получен корректный CRC, но иной формат данных; проверьте модификацию/прошивку |
| `serial_overflow` | Переполнение RX; исключите посторонний трафик/другой ведущий на линии |
| `not_polled` | Первый опрос ещё не выполнен |

Прошивка не отправляет команды записи, изменения тарифов, часов, адреса,
паролей или управления нагрузкой. API не имеет маршрута для произвольной
передачи команд. Доступ по HTTP предназначен для доверенной локальной сети;
на самом Uno нет TLS и проверки пользователя.

В режиме ожидания HTTP-обработчик ограничивает длину первой строки, общий
объём заголовков и время чтения. Счётчик опрашивается синхронно, поэтому при
таймауте прибора ответ HTTP может задержаться примерно на время опроса.
Arduino является единственным ведущим на своей линии; не запускайте на ней
одновременно конфигуратор или второй опрашивающий контроллер.

## Проверки без платы

```bash
sh tests/run.sh
```

Нужен `g++`. Проверяются стандартный CRC16/MODBUS, опубликованные запрос и
ответ Wiren Board, адрес фотографии, декодирование BCD, ошибочный CRC/BCD,
неполный кадр, другой адрес/команда, эхо и восстановление потока после мусора.
Эти проверки не заменяют измерения UART и реальный обмен со счётчиком.
