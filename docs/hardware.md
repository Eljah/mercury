# Подключение «Меркурия-200» к Arduino и Raspberry Pi

Схемы рассчитаны на **проводной CAN-интерфейс «Меркурия-200» в реализации изготовителя**. На фотографии маркировка похожа на `200.03`; последняя цифра не вполне читается. Здесь передаются байты UART через физический приёмопередатчик CAN. Обычный CAN-контроллер **MCP2515, CAN-шилд с MCP2515 и SocketCAN для этой схемы не используются**. Это инженерный проект по документации: испытания на физическом счётчике пользователя ещё нужны. Основание выбора физического уровня — [разъяснение Инкотекс](https://doc.incotexcom.ru/protocol/mercury/).

## 1. Клеммы счётчика

| Клемма | Маркировка на фотографии | Соединение проекта |
|---|---|---|
| 1 | Общий провод | GND низковольтной части |
| 2 | И− | CANH приёмопередатчика |
| 3 | И+ | CANL приёмопередатчика |
| 4, 5 | +5 В | Вход внешнего питания интерфейса |

Соответствие `2 → H`, `3 → L` взято из [проверенного подключения Wiren Board к «Меркурию-200.02»](https://wiki.wirenboard.com/wiki/Mercury_200); плюс и минус в старой надписи счётчика не следует трактовать как универсальную распиновку RS-485. Перед сборкой сверьте свою клеммную наклейку. Для варианта `.05` с RS-485 нужна другая схема физического интерфейса.

Интерфейсу нужно стабилизированное **5 В**; рабочий диапазон по [руководству серии](https://doc.incotexcom.ru/hardware/200/) — 4,5–5,5 В, для источника рекомендуется запас выходного тока не менее 250 мА. Это питание интерфейса, его нельзя считать заменой штатного питания самого счётчика. Клеммы 4 и 5 отмечены одним назначением; в данной схеме питание подаётся на клемму 4, клемма 5 остаётся свободной.

Соединяйте CANH/CANL одной скрученной парой. GND и +5 В — отдельные жилы. Для первого запуска используйте короткий кабель 0,5–2 м и только один опрашивающий контроллер. Не присоединяйте второй master к действующей системе диспетчеризации без согласования её работы.

**Клемма 1 — общий провод интерфейса, а не сетевой ноль и не защитное заземление.** Силовые клеммы 6–9 в этот проект не входят. Все изменения проводки выполняются при отключённом сетевом напряжении; монтаж в щите должен выполнять квалифицированный специалист. Низковольтный блок питания должен иметь безопасную изоляцию от сети. Приёмопередатчики ниже сами по себе гальванической развязки не дают.

## 2. Arduino Uno R3 / Nano classic 5 В + W5500

### Детали

- Uno R3 либо Nano classic на ATmega328P, 5 В / 16 МГц.
- Arduino Ethernet Shield 2 на W5500 для Uno. Для Nano — W5500-модуль с питанием и логическими входами, явно совместимыми с выбранной платой 5 В; напряжение питания безымянного модуля нужно проверить по его документации.
- **PCA82C250T**, отдельный приёмопередатчик или модуль с доступными TXD/RXD/CANH/CANL. Не заменять произвольным «CAN module».
- Керамический конденсатор 100 нФ; подтяжка 10 кОм; макетная плата/переходник SO8; клеммы и кабель.
- Два резистора 120 Ом с возможностью отключения, если согласование потребуется.

### Соединения PCA82C250T

Номера — выводы самой микросхемы SO8; у готового модуля ориентируйтесь по названиям сигналов.

| Вывод PCA82C250T | Куда соединить |
|---|---|
| 1 — TXD | Arduino **D9**, передача SoftwareSerial |
| 2 — GND | Arduino GND и клемма 1 счётчика |
| 3 — VCC | Стабилизированные **+5 В** |
| 4 — RXD | Arduino **D8**, приём SoftwareSerial |
| 5 — Vref | Оставить неподключённым |
| 6 — CANL | Клемма **3** счётчика |
| 7 — CANH | Клемма **2** счётчика |
| 8 — Rs | GND, нормальный быстрый режим |

Установите **100 нФ между выводами 3 и 2**, максимально близко к микросхеме. Добавьте **10 кОм между TXD (1) и +5 В**: это наша дополнительная подтяжка, удерживающая передатчик в состоянии покоя, пока Arduino сбрасывается или его GPIO ещё настроен как вход. Сам PCA82C250 также предусматривает recessive-состояние при плавающем TXD. Распиновка, диапазон питания и таблица состояний: [NXP PCA82C250, разделы 7–10](https://www.nxp.com/docs/en/data-sheet/PCA82C250.pdf).

В выбранной реализации UART имеет обычную полярность: покой TXD = 1. Сигнал инверсии в SoftwareSerial включать не нужно. Выводы D0/D1 свободны для USB-загрузки и журнала.

### Соединения Ethernet

| Сигнал W5500 | Arduino Uno/Nano |
|---|---|
| CS / SCS | D10 |
| MOSI | D11 |
| MISO | D12 |
| SCK | D13 |
| GND | GND |
| CS карты SD на Shield 2 | D4: OUTPUT, HIGH, когда SD не используется |

У Uno Ethernet Shield 2 устанавливается штатно; таблица поясняет занятые выводы. Код использует D8/D9 и не пересекается с SPI. [Документация Arduino Ethernet](https://docs.arduino.cc/libraries/ethernet/) и [указание Arduino о выключении SD через D4](https://store-usa.arduino.cc/products/arduino-ethernet-shield-2).

Питание интерфейса счётчика и PCA82C250 должно иметь общую низковольтную землю с Arduino. Если Arduino уже питается по USB, **не соединяйте его шину +5 В с выходом независимого второго БП**. Можно питать интерфейс отдельным 5-вольтовым источником с общей землёй, включая обе части перед опросом; либо спроектировать общее питание от одного источника. Для постоянного монтажа нужен корпус и надёжные клеммы.

## 3. Raspberry Pi через UART на GPIO

Основная инструкция — для **Pi 3 / Pi 4 / Zero 2 W** с 40-контактным разъёмом. Используется аппаратный UART, а не программное переключение GPIO. Ethernet или Wi-Fi предоставляет сам Raspberry Pi.

### Детали и соединения

Нужен **SN65HVD230** на 3,3 В, конденсатор 100 нФ и подтяжка 10 кОм. Подходит модуль с выведенными `D/TXD`, `R/RXD`, `CANH`, `CANL` и доступной настройкой `Rs`; проверьте встроенные резисторы модуля.

| Вывод SN65HVD230 | Raspberry Pi / счётчик |
|---|---|
| 1 — D, вход передатчика | **GPIO14 / TXD**, физический контакт **8** |
| 2 — GND | GND Pi, например контакт **6**, и клемма **1** |
| 3 — VCC | **3,3 В**, физический контакт **1** Pi |
| 4 — R, выход приёмника | **GPIO15 / RXD**, физический контакт **10** |
| 5 — Vref | Оставить неподключённым |
| 6 — CANL | Клемма **3** счётчика |
| 7 — CANH | Клемма **2** счётчика |
| 8 — Rs | GND |
| Питание счётчика, клемма 4 | **5 В**, не 3,3 В |

Конденсатор **100 нФ — между выводами 3/2**. Подтяжка **10 кОм — от D (1) к 3,3 В**. VCC SN65HVD230 и подтяжку нельзя подключать к 5 В. TI подтверждает совместимость его 3,3-вольтового физического CAN-интерфейса с 5-вольтовыми CAN-приёмопередатчиками: [datasheet, разделы 7, 10, 11.3 и 12](https://www.ti.com/lit/ds/symlink/sn65hvd230.pdf).

Для короткого соединения питание интерфейса счётчика можно взять с **5-вольтового контакта 4** Raspberry Pi, если у штатного БП и кабеля есть запас не менее 250 мА сверх потребления Pi и периферии. При отдельном БП объединяют только земли; его положительный выход не соединяют с 5-вольтовой шиной уже запитанного Pi.

GPIO Raspberry Pi работают на 3,3 В и не допускают 5 В. Поэтому PCA82C250 из Arduino-схемы нельзя просто перенести на Pi: его RXD имеет 5-вольтовые уровни. [Официальное описание GPIO](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html#gpio).

### Настройка UART Pi 3/4/Zero 2 W

1. В `sudo raspi-config` откройте раздел Serial Port: **login shell — No**, **serial hardware — Yes**.
2. Для предсказуемого PL011 в `/boot/firmware/config.txt` (на старых образах `/boot/config.txt`) добавьте, не дублируя существующие настройки:

   ```ini
   enable_uart=1
   dtoverlay=disable-bt
   ```

3. Эта конфигурация отключает Bluetooth. Выполните `sudo systemctl disable hciuart`, затем перезагрузите Pi.
4. Убедитесь, что в единственной строке `cmdline.txt` нет `console=serial0,...` либо `console=ttyAMA0,...`. Остальные параметры загрузки сохраняются. `enable_uart=1` само по себе консоль не выключает.
5. Проверьте `readlink -f /dev/serial0`. Для этой конфигурации ожидается `/dev/ttyAMA0`. Перед опросом проверьте, что последовательный порт не занят другим процессом.

Подробности маршрутизации и отключения консоли: [официальная документация Raspberry Pi](https://www.raspberrypi.com/documentation/computers/configuration.html#configuring-uarts).

**Pi 5:** его `/dev/serial0` по умолчанию относится к отладочному UART `/dev/ttyAMA10`, поэтому нельзя подставлять его вслепую для контактов 8/10. Для UART на гребёнке используется отдельная настройка `uart0-pi5` и проверяется фактический `/dev/ttyAMA*`. Pi 5 не является основным проверяемым вариантом этой инструкции; назначение порта зависит от образа ОС и Device Tree. Это не мешает самому протоколу программы, где путь последовательного порта настраивается.

## 4. Согласование линии и эхо

Если линия требует согласования, ставятся **120 Ом между CANH/CANL на двух физических концах**. Сначала проверьте, нет ли резистора уже на модуле: не добавляйте параллельно ещё один автоматически. Руководство счётчика допускает не устанавливать согласующие резисторы при суммарной длине линии менее 5 м. Начинайте со стенда 0,5–2 м. На длинной линии также проверяется напряжение 5 В непосредственно на счётчике. [Инкотекс: рекомендации по интерфейсам](https://doc.incotexcom.ru/hardware/200/).

У выбранных приёмопередатчиков приёмник остаётся включённым и отражает состояние общей шины: во время передачи на RX может вернуться собственный запрос. Это ожидаемое **эхо**, а не ответ счётчика. Программа должна искать ответ нужного адреса/команды, проверять длину и CRC; первые байты нельзя безусловно считать показаниями. У SoftwareSerial Arduino часть/всё локальное эхо может не приниматься во время передачи, у аппаратного UART Pi оно обычно присутствует.

Полярность следует из таблиц состояний обоих приёмопередатчиков: UART `0` создаёт CANH выше CANL; приёмник выдаёт `0`. При `1` передатчик освобождает шину. Во время ожидания ответа TX остаётся в `1`; отдельного сигнала DE, как у MAX485, в этих схемах нет.

## 5. Почему здесь не выбран MCP2562

У MCP2561/2 предусмотрено прекращение слишком длинного dominant-состояния: в [datasheet Microchip](https://ww1.microchip.com/downloads/en/DeviceDoc/20005167C.pdf) для таймера указано только типовое значение 1,25 мс, а минимальная гарантированная скорость стандартного режима — 14,4 кбит/с. При UART 9600 байт `00` удерживает передатчик в нуле 9/9600 = **0,9375 мс**. Типового значения недостаточно для гарантии во всём диапазоне условий. Поэтому в проекте выбраны PCA82C250 и SN65HVD230, у которых такой таймер не описан. Не заменяйте их другими CAN-чипами без проверки этого ограничения; некоторые современные приёмопередатчики срезают UART-последовательности даже при исправной распиновке.

## 6. Проверка перед первым реальным опросом

1. Сверить модификацию и клеммную маркировку счётчика; при несовпадении остановить сборку и пересмотреть схему.
2. На обесточенной сборке проверить отсутствие соединения интерфейсной земли с силовыми клеммами, коротких замыканий питания и лишних терминаторов.
3. До соединения UART с Pi измерить питание модуля и уровень его RX: в Pi-схеме они должны быть в пределах 3,3-вольтовой логики.
4. Проверить передачу запроса логическим анализатором на низковольтной стороне: обычный UART 9600 8N1, адрес `651401`, команда чтения `0x27`. Не выполнять команды записи ради проверки связи.
5. Сравнить первый успешно прочитанный результат с дисплеем счётчика. До этого этапа нельзя считать совместимость конкретного прибора 2006 года подтверждённой.
