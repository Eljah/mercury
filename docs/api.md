# HTTP API, версия 1

Оба устройства предоставляют только чтение: `GET /api/v1/readings` и `GET /health`. Эти адреса возвращают один и тот же JSON-кэш. HTTP-запрос не инициирует дополнительного обмена со счётчиком. Изменять конфигурацию счётчика через сеть нельзя.

## Пример успешного ответа

Это **пример синтетических данных**, не показания счётчика с фотографии:

```json
{
  "schema_version": 1,
  "device": "mercury-200",
  "transport": "raspberry-pi-uart-can",
  "meter_address": 651401,
  "demo": true,
  "ok": true,
  "error": null,
  "has_reading": true,
  "age_seconds": 2,
  "captured_at": "2026-10-26T10:00:00Z",
  "tariffs_kwh": [1234.56, 78.90, 0.00, 0.00],
  "total_kwh": 1313.46
}
```

| Поле | Значение |
|---|---|
| `schema_version` | Сейчас `1` |
| `device` | Семейство протокола, `mercury-200`; не результат автоматического определения суффикса |
| `transport` | `arduino-uart-can` либо `raspberry-pi-uart-can` |
| `meter_address` | Адрес, заданный в конфигурации |
| `demo` | `true` только у синтетического режима Java; в Arduino всегда `false` |
| `ok` | Последняя попытка опроса была успешной; у Pi дополнительно проверяется свежесть выборки |
| `error` | `null` при успехе, иначе строка с причиной |
| `has_reading` | Получена хотя бы одна корректная выборка с начала запуска |
| `age_seconds` | Возраст последней успешной выборки; `null`, если её ещё нет |
| `captured_at` | Время последней успешной выборки в UTC у Pi; у Arduino `null` (RTC/NTP не настроены) |
| `tariffs_kwh` | Массив `[T1,T2,T3,T4]` в кВт·ч либо `null`; точность 0,01 кВт·ч |
| `total_kwh` | Сумма четырёх тарифов, вычисленная программой, либо `null` |

Внутри программы показания хранятся целыми сотыми кВт·ч. Для хранения десятичных значений в другой Java-программе используйте `BigDecimal` или целые сотые; не требуется переводить их в двоичный `float`.

## Сбой и старые данные

- **HTTP 200:** доступна последняя успешная выборка, `ok:true`.
- **HTTP 503:** ответ не получен, повреждён либо данные устарели; `ok:false`.
- До первого успешного чтения: `has_reading:false`, `tariffs_kwh:null`, `total_kwh:null`, `age_seconds:null`.
- Если предыдущая выборка есть, при сбое она сохраняется, но `ok:false`. Она не становится новой только потому, что была выдана по HTTP ещё раз.
- Java-сервис также считает данные устаревшими после приблизительно трёх периодов опроса плюс таймаут. Arduino ориентируется на результат последнего опроса; возраст измеряется `millis()` и переполняется после примерно 49 суток непрерывного отсутствия нового успешного чтения. Ошибочный статус при этом остаётся.

Разные платформы могут возвращать разные диагностические строки `error`: Arduino различает `timeout`, `crc_error`, `invalid_bcd`, `serial_overflow`, `invalid_frame`, `not_polled`; Java возвращает `poll_failed`, подробность пишет в журнал, а для устаревшей выборки использует `stale_reading`.

Неподдерживаемый путь — 404, метод кроме GET — 405. Доступ предназначен для локальной сети. API не имеет endpoint для произвольной отправки пакетов или записи в счётчик.
