# Raspberry Pi: Меркурий-200 → UART на GPIO → Java → локальная сеть

Готовый Maven-проект Java 17. Считывает накопленную энергию по четырём тарифам командой `0x27`, проверяет ответ и отдаёт JSON по HTTP. Библиотека доступа к последовательному порту — `jSerialComm 2.11.4`; её нативные библиотеки для Linux ARM включаются в итоговый JAR.

**Физическое подключение:** UART GPIO14/GPIO15 через приёмопередатчик **SN65HVD230, питание 3,3 В**, к CAN-интерфейсу «Меркурия». В этом проекте нет CAN-контроллера, MCP2515, SocketCAN и формирования обычных CAN-кадров. См. точную схему, питание интерфейса счётчика и согласование линии в [общем описании аппаратуры](../docs/hardware.md).

Проверка на настоящем счётчике и на Raspberry Pi в процессе подготовки проекта не выполнялась. Программные проверки не заменяют первую проверку электрического подключения и фактической скорости/адреса вашего экземпляра. По фото модель читается предположительно как `200.03`; алгоритм чтения проверяется по опубликованным тестовым кадрам серии «Меркурий-200».

## 1. Проверка программы без счётчика

Нужна Java 17 или более новая. Для первого запуска удобно Java 17/21. Готовый JAR входит в общий комплект; если собираете из исходников:

```bash
mvn clean verify
java -jar target/mercury-pi.jar --demo --bind 127.0.0.1 --port 8080
```

Из другого терминала:

```bash
curl -i http://127.0.0.1:8080/api/v1/readings
```

Demo не открывает последовательный порт и не требует GPIO. Значения `1234.56, 789.01, 0.00, 0.00` **синтетические**, не снятые со счётчика. Во всех ответах этого режима будет `"demo":true`, при старте выводится `DEMO: readings are SYNTHETIC`. Для настоящего подключения уберите `--demo` и оставьте `demo=false` в конфигурации. Демонстрация может работать и на Windows.

## 2. GPIO и Raspberry Pi OS

Основная инструкция рассчитана на Raspberry Pi 3, 4 и Zero 2 W с 40-контактным разъёмом. Raspberry Pi с Ethernet использует свою обычную сетевую карту; Zero 2 W может передавать тот же HTTP по Wi-Fi.

| Назначение | Номер GPIO (BCM) | Физический контакт разъёма |
|---|---:|---:|
| UART TX → вход D приёмопередатчика | GPIO14 | 8 |
| UART RX ← выход R приёмопередатчика | GPIO15 | 10 |
| Общий провод | — | 6 |
| 3,3 В для SN65HVD230 | — | 1 |

К сигнальным GPIO нельзя подключать клеммы счётчика напрямую или подавать 5 В. Питание интерфейса самого счётчика +5 В является отдельной цепью. Полная схема приведена в `../docs/hardware.md`.

### Настройка UART на Pi 3 / Pi 4 / Zero 2 W

```bash
sudo raspi-config
```

В `Interface Options → Serial Port`:

1. На вопрос о login shell через serial — **No**.
2. На вопрос о включении serial hardware — **Yes**.
3. Перезагрузить Pi.

После перезагрузки:

```bash
readlink -f /dev/serial0
ls -l /dev/serial0
groups
```

Пользователю требуется доступ к группе `dialout`:

```bash
sudo usermod -aG dialout "$USER"
```

Затем выйдите из сеанса и войдите заново. Программа не требует запуска от root. Порт должен быть свободен: его одновременно не должны использовать login console, конфигуратор счётчика или другая программа. GPIO14/15 должны быть назначены UART; файл `/dev/serial0` служит системным псевдонимом соответствующего UART на поддерживаемых здесь моделях.

У Pi 3/4/Zero 2 W тип UART зависит от конфигурации Bluetooth. Для основной инструкции достаточно включения аппаратного UART через `raspi-config`; если изменяете частоты или UART overlays вручную, сверьтесь с документацией Raspberry Pi. Java-программа не переназначает контакты и не редактирует `/boot/firmware/config.txt`.

### Raspberry Pi 5

На Pi 5 `/dev/serial0` по умолчанию относится к отдельному debug UART, а не обязательно к контактам 8/10. Не переносите этот путь механически с Pi 4. Включите UART на GPIO14/15 по разделу Pi 5 в общей инструкции по аппаратуре и укажите в `serial.device` фактическое устройство этого UART. Программа допускает любой явно заданный путь устройства; стандартные CAN-устройства `can0` сюда не подходят.

## 3. Настройки вашего счётчика

В `config.properties` заданы:

```properties
meter.address=651401
serial.device=/dev/serial0
serial.baud=9600
serial.timeout.ms=1500
poll.seconds=30
http.bind=0.0.0.0
http.port=8080
demo=false
```

`651401` — предполагаемый заводской адрес из номера на фото `00651401`. Если адрес был изменён, задайте фактический. Скорость **9600 8N1** должна совпадать с настройкой прибора; этот комплект намеренно принимает только 9600 и не пытается менять настройки счётчика. Если старый прибор отвечает на другой скорости, сначала нужно отдельно подтвердить её и пересмотреть аппаратную совместимость; отправка команд изменения скорости в проект не включена.

Читается только команда `0x27`: тарифы T1–T4. Нет команд записи времени, тарифного расписания, адреса, отключения нагрузки или сброса. `total_kwh` вычисляется как сумма четырёх накопленных значений. Это не мощность и не расход за текущий месяц. Для расхода за период нужно вычитать два накопленных значения, учитывая возможную замену/сброс счётчика.

**Файл конфигурации читается только при явном `--config`.** Это исключает неожиданное влияние одноимённых файлов в каталоге запуска.

```bash
java -jar target/mercury-pi.jar --config config.properties
```

Допустимы переопределения из командной строки:

```bash
java -jar target/mercury-pi.jar --config config.properties --device /dev/ttyAMA0 --address 651401
```

Путь `/dev/ttyAMA0` в последнем примере — лишь пример переопределения; используйте путь, соответствующий вашему UART.

## 4. Доступ по сети и API

При `http.bind=0.0.0.0` сервис слушает все сетевые интерфейсы Pi. Узнайте его локальный адрес командой `hostname -I`. Откройте с компьютера в той же сети:

```text
http://IP_ВАШЕГО_PI:8080/api/v1/readings
http://IP_ВАШЕГО_PI:8080/health
```

Это сервис для доверенной локальной сети: в нём нет аутентификации и TLS. Проброс порта в Интернет для работы не нужен. Если приложение должно быть доступно только на Pi, установите `http.bind=127.0.0.1`.

Успешный ответ содержит:

```json
{
  "schema_version": 1,
  "device": "mercury-200",
  "transport": "raspberry-pi-uart-can",
  "meter_address": 651401,
  "demo": false,
  "ok": true,
  "error": null,
  "has_reading": true,
  "age_seconds": 2,
  "captured_at": "2026-10-26T10:00:00Z",
  "tariffs_kwh": [621.42, 208.34, 111.11, 222.22],
  "total_kwh": 1163.09
}
```

Этот JSON иллюстрирует формат; значения взяты из опубликованного тестового кадра, а дата приведена как пример, не как замер вашего счётчика. `captured_at` — время компьютера Pi, не чтение внутренних часов счётчика. Возраст выборки считается монотонными часами и не зависит от коррекции системного времени.

| Состояние | HTTP | Поля |
|---|---:|---|
| Последний опрос успешен | 200 | `ok=true`, `error=null` |
| До первого ответа | 503 | `has_reading=false`, `tariffs_kwh=null`, `total_kwh=null` |
| Последний опрос завершился ошибкой | 503 | `ok=false`, `error="poll_failed"`; предыдущая выборка сохранена, её возраст продолжает расти |
| Давно не было успешной публикации | 503 | `error="stale_reading"`, если последняя попытка формально была успешной |
| Любой запрос на изменение, например POST | 405 | `method_not_allowed` |

Оба GET endpoint возвращают одно и то же состояние. HTTP-запросы читают только кэш и не запускают дополнительный опрос GPIO. Опрос последовательный, один запрос за раз; после окончания попытки программа ждёт `poll.seconds` до следующей. Ошибки подробно записываются в stderr/journal, API использует стабильный код ошибки.

## 5. Готовый клиент на Java для обоих вариантов

В том же JAR находится простой сетевой клиент. Он читает JSON как из этого Pi-сервиса, так и из Arduino-проекта:

```bash
java -cp target/mercury-pi.jar ru.mercury.lan.HttpReadingsClient http://192.168.1.50/api/v1/readings
```

Для Pi укажите его адрес и порт `8080`. Периодический сбор JSON Lines каждые 30 секунд:

```bash
java -cp target/mercury-pi.jar ru.mercury.lan.HttpReadingsClient http://192.168.1.51:8080/api/v1/readings 30 > readings.jsonl
```

При HTTP 503 клиент выводит тело состояния и отдельное сообщение в stderr; в одиночном режиме завершает работу с кодом 1. При сетевой ошибке завершается с исключением: для автономного длительного сбора его можно запускать под systemd/планировщиком либо расширить своей политикой повторов. Значения `demo`, `ok` и `age_seconds` должны проверяться потребителем данных.

## 6. Автозапуск на Raspberry Pi

Установите Java 17/21 (пакет `default-jre-headless` в подходящем выпуске Raspberry Pi OS), затем проверьте `java -version`. Для сборки на Pi дополнительно нужны JDK и Maven; готовому JAR Maven не требуется.

После успешного ручного чтения:

```bash
sudo useradd --system --user-group --groups dialout --home-dir /opt/mercury-pi --shell /usr/sbin/nologin mercury
sudo install -d -m 0755 /opt/mercury-pi /etc/mercury-pi
sudo install -m 0644 target/mercury-pi.jar /opt/mercury-pi/mercury-pi.jar
sudo install -m 0644 config.properties /etc/mercury-pi/config.properties
sudo install -m 0644 deploy/mercury-pi.service /etc/systemd/system/mercury-pi.service
sudo systemctl daemon-reload
sudo systemctl enable --now mercury-pi
```

Если пользователь `mercury` уже существует, повторно создавать его не нужно; проверьте, что он входит в `dialout`. Изменения в установленном конфигурационном файле вступают в силу после `sudo systemctl restart mercury-pi`.

```bash
systemctl status mercury-pi
journalctl -u mercury-pi -n 50 --no-pager
```

Настройка `PrivateTmp=true` даёт библиотеке отдельный временный каталог для извлечения ARM-библиотеки. Если политика вашей системы запрещает запуск библиотек из временных каталогов, настройку jSerialComm следует адаптировать по её документации. Для Java 24+ может потребоваться `--enable-native-access=ALL-UNNAMED` перед `-jar`; проект собирается и проверяется на Java 17.

## 7. Что проверяют тесты

```bash
mvn test
```

Тесты используют независимые опубликованные кадры Wiren Board: запрос `FE 12 34 56 27 36 D8` и ответ с тарифами `621.42 / 208.34 / 111.11 / 222.22`. Проверяются порядок байтов, CRC, BCD, неверный адрес/код, усечённый пакет, повреждение данных, локальное эхо передачи, шум перед ответом, сохранение предыдущей выборки при ошибке, HTTP 200/503/404/405 и явная маркировка demo.

Протокольный разбор использует фиксированное окно 23 байта. Последовательный транспорт принимает максимум 4096 байт за попытку и ограничен общим timeout. Наличие эха не является обязательным: одинаково поддерживаются эхо и его отсутствие. Отсутствие ответа никогда не преобразуется в «нулевое потребление».
