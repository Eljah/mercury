# mercury

Программа для связи со старым счётчиком «Меркурий-200»: Arduino Ethernet и Raspberry Pi GPIO.


Два самостоятельных проекта чтения накопленных показаний **T1–T4** по проводному интерфейсу счётчика. Оба публикуют одинаковый HTTP/JSON API, который можно читать из любой Java-программы. Вариант Raspberry Pi сам написан на **Java 17**, собирается Maven и поставляется запускаемым JAR со всеми зависимостями.

Версия 1.0.0, 26 октября 2026 года.

## Что учтено именно для вашего счётчика

- На фотографии — семейство «Меркурий-200», вероятнее всего `200.03`, 2006 год. Суффикс на фото не читается окончательно.
- Заводской номер `00651401`, поэтому исходный адрес проекта — **651401**. Адрес мог быть изменён при настройке прибора.
- Используется **UART 9600 8N1 через физический CAN-приёмопередатчик**. Это не обычные CAN-кадры: MCP2515, SocketCAN и библиотека CAN здесь не нужны.
- Счётчик опрашивается только командой **0x27**. Записи тарифов, времени, адреса и управления нагрузкой в проектах нет.
- Программная часть собрана и проверена; обмен с вашим физическим экземпляром и готовая электронная сборка ещё не проверялись. Подробные пределы проверки — [docs/validation.md](docs/validation.md).

## Два варианта

| | Arduino | Raspberry Pi |
|---|---|---|
| Плата | Uno R3 / Nano classic, ATmega328P, 5 В | Pi 3 / Pi 4 / Zero 2 W |
| Сеть | W5500, Ethernet | Ethernet или Wi-Fi самой Pi |
| Физический интерфейс счётчика | PCA82C250T, 5 В | SN65HVD230, 3,3 В |
| UART | RX D8, TX D9 | GPIO14 TX, GPIO15 RX; физические контакты 8/10 |
| Программа | Arduino C++, исходники и HEX | Java 17, исходники Maven и готовый fat JAR |
| Период опроса | 30 секунд | 30 секунд |
| Адрес API по умолчанию | `http://192.168.1.50/api/v1/readings` | `http://IP_ВАШЕЙ_PI:8080/api/v1/readings` |

Если Pi уже есть, этот вариант удобен для доработки Java-кода и хранения истории. Arduino — отдельный небольшой сетевой опрашиватель с ограниченным объёмом памяти.

## Содержимое

- `arduino/` — скетч, конфигурация, PlatformIO, тесты декодера и своя инструкция.
- `raspberry-pi/` — Maven-проект, конфигурация, systemd unit, тесты и своя инструкция.
- `dist/` — готовые JAR и прошивки HEX; точные параметры сборки записаны рядом.
- `docs/hardware.md` — детали, питание, все соединения, выбор приёмопередатчиков.
- `docs/wiring-arduino.svg`, `docs/wiring-raspberry-pi.svg` — схемы соединений; открываются в браузере.
- `docs/api.md` — единый API и обработка недоступности показаний.
- `docs/protocol.md` — формат пакетов и контрольные примеры.
- `tests/serial_integration.py` — интеграционная проверка Java-сервиса через псевдотерминал Linux, без физического GPIO.

## Сначала проверить программу без оборудования

На Windows, Linux или Raspberry Pi с Java 17 или новее, из корня распакованного архива:

```bash
java -jar dist/mercury-pi.jar --demo --bind 127.0.0.1 --port 8080
```

Откройте `http://127.0.0.1:8080/api/v1/readings`. Все такие показания **синтетические**, в JSON есть `demo:true`. В этом режиме последовательный порт не открывается. Завершение — Ctrl+C.

В другом терминале тот же архив можно использовать как готовый Java-клиент:

```bash
java -cp dist/mercury-pi.jar ru.mercury.lan.HttpReadingsClient http://127.0.0.1:8080/api/v1/readings
```

## Arduino: первый запуск

1. Соберите низковольтные соединения по [аппаратной инструкции](docs/hardware.md). Основной вариант — Uno + Ethernet Shield 2 + отдельный PCA82C250T. Интерфейсу счётчика нужно внешнее **5 В**.
2. Откройте `arduino/MercuryLan/MercuryLan.ino` в Arduino IDE.
3. Установите **Arduino AVR Boards 1.8.6**, библиотеку **Ethernet 2.0.2**, выберите свою плату и COM-порт.
4. В `config.h` проверьте адрес счётчика и параметры своей сети. `192.168.1.50` — пример исходной настройки, он должен быть свободен и находиться в вашей подсети. Для нескольких устройств нужны разные IP и MAC.
5. Загрузите скетч. Монитор USB-порта, 115200 бод, покажет IP.
6. Откройте `http://IP_ARDUINO/api/v1/readings` и сравните T1/T2 с дисплеем счётчика.

Готовые HEX в `dist/` собраны с исходной конфигурацией. Если меняете адрес или IP, пересобирайте исходники. Для Nano выбор старого/нового загрузчика выполняется в Arduino IDE; HEX прикладной программы загрузчик не содержит.

Дополнительные команды CLI/PlatformIO: [arduino/README.md](arduino/README.md).

## Raspberry Pi: первый запуск через GPIO

1. Соедините Pi со счётчиком через **SN65HVD230**, как описано в [docs/hardware.md](docs/hardware.md). UART Pi и питание SN65HVD230 — **3,3 В**; питание интерфейса счётчика — **5 В**. Эти цепи питания не взаимозаменяемы.
2. В `sudo raspi-config` выключите login shell на последовательном порту и включите сам UART. Выбор PL011 и нюансы Pi 5 описаны в аппаратной инструкции. Для рекомендуемой конфигурации Pi 3/4/Zero 2 используется `disable-bt`, отключающий Bluetooth.
3. Установите Java 17+ и добавьте пользователя запуска в группу `dialout` (затем войдите заново):

   ```bash
   sudo usermod -aG dialout "$USER"
   ```

4. Проверьте `raspberry-pi/config.properties`: адрес, путь UART, порт HTTP. Запустите из корня архива:

   ```bash
   java -jar dist/mercury-pi.jar --config raspberry-pi/config.properties
   ```

5. На другом компьютере откройте `http://IP_ВАШЕЙ_PI:8080/api/v1/readings`.

Для этой версии не требуется root-доступ программы и не нужна библиотека прямого управления GPIO: драйвер ОС предоставляет UART как `/dev/serial0`. На **Pi 5** это имя по умолчанию относится к другому, отладочному разъёму; проверьте Device Tree и задайте реальное имя UART контактов 8/10.

Сборка исходников — `mvn clean package` в `raspberry-pi/`. Подробная установка и systemd: [raspberry-pi/README.md](raspberry-pi/README.md).

## Читать из Java и сохранять журнал

Один запрос к Arduino:

```bash
java -cp dist/mercury-pi.jar ru.mercury.lan.HttpReadingsClient http://192.168.1.50/api/v1/readings
```

Опрос Raspberry Pi раз в минуту и запись JSON Lines:

```bash
java -cp dist/mercury-pi.jar ru.mercury.lan.HttpReadingsClient http://192.168.1.51:8080/api/v1/readings 60 >> readings.jsonl
```

Клиент читает сетевой API; он не требует последовательного порта на компьютере. Исходник — `raspberry-pi/src/main/java/ru/mercury/lan/HttpReadingsClient.java`. В этой версии он сохраняет полученный JSON целиком, а не преобразует его в CSV.

`ok:false` и HTTP 503 означают сбой последнего опроса. Старая успешная выборка может оставаться в ответе для диагностики: это видно по `age_seconds`. Не записывайте её как новый замер. До первого успешного чтения значения — `null`, а не выдуманный ноль. Проверяйте также `demo:false` при работе с настоящим счётчиком.

## Границы первой версии

- Реализованы накопленная активная энергия T1–T4 и их сумма. Напряжение, ток, мгновенная мощность и месячный архив пока не опрашиваются: для старого прибора сначала нужно подтвердить поддержку соответствующих команд.
- Опрос ведёт только один контроллер. Arduino и Pi — альтернативы, подключать их одновременно как два master к одной шине нельзя.
- Исходные аппаратные варианты рассчитаны на короткую линию; согласование и питание длинной линии описаны отдельно.
- HTTP API предназначен для своей локальной сети; аутентификации и TLS на самих устройствах нет. Удалённое использование — через существующий VPN или защищённый шлюз.
- Приёмопередатчик преобразует электрические уровни, но сам не создаёт гальваническую развязку. Силовая часть 220 В не входит в схемы проекта.
- Схемы и прошивка не меняют тарифы, время или учётные регистры счётчика. Реальная совместимость именно `200.03` 2006 года подтверждается первым корректным ответом и сверкой с дисплеем, а не только успешной компиляцией.
